## 1. Project Overview

This project demonstrates the development of a **Playwright automation testing framework using JavaScript, Page Object Model (POM), JSON-driven test data, and Command Line Interface (CLI) execution**.

The framework automates the login functionality of the [SauceDemo](https://www.saucedemo.com/) web application.

The primary objective is to build a structured, reusable, and maintainable automation framework that can validate both successful and unsuccessful login scenarios.

The project was developed with AI assistance, followed by manual review, implementation, execution, and validation of the generated code.

## 2. Project Objectives

The main objectives of this project are:

- Set up a Playwright automation project using JavaScript.
- Implement the Page Object Model (POM) design pattern.
- Create reusable LoginPage and InventoryPage classes.
- Store test credentials and expected results in a JSON file.
- Implement data-driven testing using JSON records.
- Automate positive and negative login scenarios.
- Execute tests using npm CLI commands.
- Generate Playwright HTML and Allure reports.
- Organize the project using a maintainable folder structure.
- Upload the completed framework to GitHub.

## 5. Framework Architecture — Page Object Model

The framework uses the Page Object Model design pattern to separate page locators and browser interactions from test logic.

### 5.1 LoginPage.js

Location: `pages/LoginPage.js`

The LoginPage class represents the SauceDemo login page.

It contains the following locators:

- `usernameInput` — Username input field.
- `passwordInput` — Password input field.
- `loginButton` — Login button.
- `errorMessage` — Login error message.

**Implemented methods:**

- `login(username, password)` — Enters the provided credentials and clicks the login button.
- `getErrorMessage()` — Retrieves the login error message.

### 5.2 InventoryPage.js

Location: `pages/InventoryPage.js`

The InventoryPage class represents the product inventory page displayed after a successful login.

It contains the following locators:

- `pageTitle` — Inventory page title.
- `productList` — Product listing container.

**Implemented method:**

- `isLoaded()` — Checks whether the inventory page title is visible, the title is `Products`, and the product list is visible.

### 5.3 Benefits of POM

Using POM provides:

- Reusable page interaction methods.
- Separation of test logic and page-specific logic.
- Easier maintenance of locators.
- Better readability.
- Improved scalability for future automation tests.

## 6. Test Data Management — JSON

Location: `data/users.json`

Test credentials and expected outcomes are maintained separately from the test implementation.

The JSON file contains three test scenarios:

| Username | Password | Expected Result |
|---|---|---|
| standard_user | secret_sauce | success |
| locked_out_user | secret_sauce | error |
| standard_user | wrong_password | error |

This approach allows multiple test scenarios to be executed without duplicating the test implementation.

## 7. Automated Test Implementation

Location: `tests/login.spec.js`

The test file imports:

- Playwright's `test` and `expect` functions.
- LoginPage class.
- InventoryPage class.
- User test data from `users.json`.

The framework uses JavaScript's `forEach()` method to generate individual tests from the JSON records.

### Test Scenario 1: Successful Login

**Test data:**
- Username: `standard_user`
- Password: `secret_sauce`

**Expected behavior:**

1. Navigate to SauceDemo.
2. Enter valid login credentials.
3. Click the login button.
4. Verify that the inventory page title displays `Products`.
5. Verify that the inventory page is loaded successfully.

### Test Scenario 2: Locked-Out User

**Test data:**
- Username: `locked_out_user`
- Password: `secret_sauce`

**Expected behavior:**

1. Navigate to SauceDemo.
2. Enter the locked-out user's credentials.
3. Click the login button.
4. Verify that the login error message is visible.
5. Verify that the error message is not empty.

### Test Scenario 3: Invalid Password

**Test data:**
- Username: `standard_user`
- Password: `wrong_password`

**Expected behavior:**

1. Navigate to SauceDemo.
2. Enter an incorrect password.
3. Click the login button.
4. Verify that the login error message is visible.
5. Verify that the error message is not empty.

## 8. Playwright Configuration

Location: `playwright.config.js`

The configuration file defines the test execution environment and reporting options.

**Configuration details:**

| Setting | Configuration |
|---|---|
| Test directory | `./tests` |
| Test timeout | 30,000 milliseconds |
| Browser | Chromium |
| Base URL | https://www.saucedemo.com |
| Headless mode | false |
| HTML reporter | Enabled |
| Allure reporter | Enabled |

Two reporting systems are configured:

1. Playwright HTML Reporter.
2. Allure Playwright Reporter.

The HTML reporter generates the Playwright report inside `playwright-report`.

The Allure reporter stores raw execution results inside `allure-results`, which are then converted into a complete HTML dashboard.

## 9. Command Line Interface (CLI) Execution

The project uses npm scripts to simplify test execution.

### 9.1 Install Project Dependencies

After cloning the repository, navigate to the project directory:

```powershell
cd "Module 09/Playwright_POM_CLI"
```

Install dependencies:

```powershell
npm install
```

Install the Chromium browser if it is not already installed:

```powershell
npx playwright install chromium
```

### 9.2 List Available Tests

```powershell
npx playwright test --list
```

This command displays the tests discovered by Playwright.

### 9.3 Execute Login Tests

```powershell
npm run test:login
```

This command executes the login test file containing all three data-driven scenarios.

### 9.4 Execute All Playwright Tests

```powershell
npm test
```

This command executes all tests available in the configured test directory.

## 11. Test Reporting

The framework supports two types of HTML reports.

### 11.1 Playwright HTML Report

Playwright generates an HTML report containing test execution details.

**Generate and open the report:**

```powershell
npx playwright show-report
```

Default report directory:

```text
playwright-report/
```

### 11.2 Allure Report

Allure provides a detailed test execution dashboard.

**Step 1 — Execute the tests:**

```powershell
npm run test:login
```

**Step 2 — Generate the Allure HTML report:**

```powershell
npx allure generate allure-results --clean -o allure-report
```

**Step 3 — Open the Allure report:**

```powershell
npx allure open allure-report
```

Generated report directory:

```text
allure-report/
```

The Allure dashboard provides test execution summaries, test suites, individual test details, and graphical reporting information.

**Important:** Allure HTML reports are generated locally and are not committed to GitHub. The framework configuration and dependencies required to regenerate them are included in the repository.
